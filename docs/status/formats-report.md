# Project filesystem and format services

Authority: pinned LDtk `2b7b5512f2f88fa281cb6492debbb26ead7838d4`, especially ProjectSaver.hx, Level/EntityInstance.toSimplifiedJson, exporter/{Csv,Tiled,GameMakerStudio2}, importer/OgmoLoader and importer/enu/*.

## Public API

- Existing `Project::load`, `from_json`, `save` remain lossless document operations. `save` supports independent external-level Save As, canonical externalization when enabled, relative asset/background/enum/FilePath/default rebasing, timestamped retained backups and retired owned level cleanup. `set_external_levels(bool)` converts storage without dropping documents.
- `save_with_exports(path) -> Result<SaveReport>` returns document save errors as Err; once saved, configured PNG/simplified/Tiled export failures appear in `SaveReport.export_errors`, with successful `outputs` preserved. No commands run implicitly in core; desktop's trusted command path owns hooks.
- `filesystem_snapshot() -> Result<FilesystemSnapshot>` / `changed_files()` detect content changes, missing resources and later creation. `save_if_unchanged(path, snapshot)` refuses outside edits before publishing. Snapshots are caller-owned so mutable document history remains compatible.
- `backup() -> Result<Option<PathBuf>>` copies the currently saved root and its saved external layout. Default `<project>/backups`, optional backupRelPath, project IID + calendar timestamp, backupLimit; unrelated directories and source Save As files are preserved.
- `export_png`, `export_png_with_options`, `export_csv`, `export_simplified`, `export_tiled`, `export_gamemaker` return created files. PNG options expose all three original image modes, background inclusion and file patterns. Aseprite/PNG/JPEG/GIF and bundled atlas decode APIs are shared with native rendering.
- `export_tiled_with_report` exposes source limitations as warnings; mixed grids, embedded atlases, padding, Aseprite image references, freely positioned tiles and first-world export are reported explicitly.
- The manual project export panel offers Tiled TMX (XML) and TMJ (JSON). Both use the same level layout, tileset and layer conversion rules. IntGrid GIDs follow the swatch order of each palette, including sparse and reordered values. Empty palettes produce an empty tile layer without a tileset image. Save-time Tiled export continues to write TMX.
- `import_ogmo` and `import_ogmo_with_report` import Ogmo 3.3+ definitions, 1D/2D grids/tiles/flips, entities/fields, offsets, and directory rows. The report surfaces unknown grid values and unsupported tile rotations.
- `parse_external_enums`, `sync_external_enums`, `apply_external_enum_sync` parse JSON/text/Haxe/CastleDB, preserve UIDs/editor metadata and source ordering, add CastleDB atlas/colors/icons, and store MD5. Used removed enums/values yield an unapplied confirmation report. Explicit rename mappings (`Enum` or `Enum.Value` keys) propagate fields/defaults/editor wrappers/biome rules; explicit enum removal tidies dependent fields.
- `migrate_to_current() -> Result<bool>` explicitly applies loader aliases, UUIDs, defaults, pre-CSV grids, old tile/entity coordinates, old tileRectsIds and legacy enum type representations. Raw load never upgrades silently.
- `list_backups`, `load_backup(backup,original)`, `restore_backup` and `restore_backup_with_exports` retain original resource resolution and all external data; backup documents cannot accidentally save over the backup. Recovery works when the original is missing or corrupt. `rename_project(new_stem)` publishes the renamed document/external tree before removing the previous owned files, and relocates metadata.
- Signed OS clipboard interoperation uses source `LDtk <version> clipboard\n----\n<Type>\n----\n<JSON>` envelopes for definitions, fields, rules and groups. Copy/paste validates dependencies, remaps owned UIDs, preserves extension JSON, and batches rule-group refresh. Group remapping supports signed IntGrid mappings and bounded output atlas offsets.
- `move_entities_between_layers(source_uid,target_uid,filter)` and `count_entities_to_transfer` accept the original `all.*`, `id.Identifier`, `tag.tag` selectors across all worlds/external levels. IID/field data remain intact, destinations are checked before mutation, and derived coordinates/TOC/references refresh together. Source tag-selection bypass of destination tags is intentionally retained; All/Identifier enforce the original compatibility behavior.
- `cleanup_identifier(input)` and `enum_value(enum_uid,input)` expose original local-enum lookup normalization; external enum IDs stay verbatim. Explicit refresh tidies genuinely absent enum values/defaults while preserving legal legacy raw wrappers such as original Chest `Heavy sword` resolving to `Heavy_sword`. Raw load and roundtrip remain lossless.

## Exact limits and deliberate differences

- GMS2 was experimental/incomplete upstream and disabled in its automatic saving path: empty entity instances, `?` IntGrid resource type, first grid tile only, no generated AutoLayer contents. This port preserves those source semantics and does not claim GameMaker runtime parity.
- Tiled supports the first world and one grid size, skips embedded atlases, lacks atlas padding/rotation/freely positioned tiles, and rejects malformed/non-JSON tile metadata as upstream does. Diagnostics accompany the report API. TMX/XML attribute formatting is semantically compatible, not byte-identical Haxe output.
- Source PNG export omits entities and normal IntGrid from composite layers; IntGrid gets tiny color-cell images. LayersAndLevels composites use solid background color while separate background PNGs include the image, and layer display alpha is applied again in that composite path, preserving upstream quirks. Native/Heaps GPU screenshot pixel equality (particularly repeated background alignment and alpha rounding) has not been established by a compiled original export oracle.
- Backup timestamps use the local calendar through platform C runtime APIs, matching upstream. Cleanup only removes retired documents known to the previous saved root within its project directory; it does not bulk-delete unrelated `.ldtkl` files. Cleanup is best effort after successful publication. On Unix, live output inode identity protects case-only renames on case-insensitive filesystems.
- Writes preflight/stage/fsync every file, publish referenced documents before the root, preserve permissions, rollback handled rename failures and sync directories on Unix. There is no filesystem-wide atomic commit or power-loss journal; arbitrary process/power loss between independent renames is not claimed atomic.
- Historical migration tests establish structural/idempotent compatibility across the pinned corpus, not byte equality to every historical source loader. Unknown extension properties are retained. Import errors fail explicitly rather than pretending unsupported inputs succeeded.

## macOS native document opening and bundle metadata

`platform_files::install() -> OpenFilesGuard` runs on the main thread before `run_native`; retain its guard for the event loop lifetime. `set_context(&egui::Context)` attaches repaint wakeups, including any startup queue, and `take_open_file() -> Option<PathBuf>` drains FIFO requests. The app routes those requests through its existing dirty-document preflight. A dedicated NSObject receives `aevt/odoc` through NSAppleEventManager; registration is repeated at AppKit's will-finish-launching notification because AppKit otherwise restores its default handler during launch. This leaves winit's application delegate intact. NSURL filesystem conversion preserves Unicode, spaces and `#` paths. Non-macOS builds have no-op implementations.

Only `.ldtk` projects are accepted/associated (case-insensitive when delivered). The original builder also associates `.ldtkl`, but standalone external levels lack project definitions and there is no implemented source route that can reconstruct their owner; the native app does not misload them as projects. `scripts/macos-info.plist` declares Editor/Alternate document handling, an imported JSON-conforming UTI and the original project icon. ## Home backup-index memory correction

A real Home run with a 13 MB recent project showed resident memory climbing while its backup index was built. `home_files::read_backups` previously read the complete JSON, built a `Value`, and constructed/tidied a complete `Project` solely to obtain `iid` and `backupRelPath`. `Project::list_backups` also decoded every complete backup, sometimes twice.

The new `Project::list_backups_at(path)` reads only those two metadata strings through `BufReader` and serde visitors; unused strings, objects and arrays are consumed with `IgnoredAny`. The instance `list_backups` shares the same discovery routine while retaining its in-memory backup settings. Home calls the metadata-only API, requires no external level/resource files, and creates no project/value tree. Each candidate backup is parsed once. Existing root-IID and legacy `backup_` directory matching, corrupt JSON fallback restricted to the root-IID directory, timestamp/crash suffixes, sorting, extensions, custom/default paths and tolerant metadata type handling remain intact. Valid non-object JSON is fully consumed and excluded, while malformed JSON still triggers the existing fallback; duplicate metadata keys retain the prior last-key behavior.

Validation: the two new core regressions pass, including streaming a 16 MiB ignored string in both the project and a backup while an allocator asserts no single allocation reaches 256 KiB. The original project-I/O suite passes 16 tests, with its separate pinned-corpus test explicitly ignored in that targeted run; core strict Clippy passes. An additional actual `home_files::read_backups` fixture includes 8 MiB of unused data and a missing external level. Its native execution and a fresh Home RSS run follow integration of the concurrent updater module; the core allocation assertion is not a replacement for whole-process resident-memory measurement.
