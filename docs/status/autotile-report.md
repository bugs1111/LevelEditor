# Deterministic autotile engine and rule editing

Implemented in `crates/ldtk-core/src/autotile.rs`, `autotile_noise.rs`, and `autotile_edit.rs`. No JavaScript/Haxe runtime is shipped. Reference: LDtk source commit `2b7b5512f2f88fa281cb6492debbb26ead7838d4`; independent numerical oracle: installed original LDtk 1.5.3 `app.asar/assets/js/renderer.js`.

## Public contracts

- `Project::rebuild_auto_layers(key: LevelKey) -> Result<()>`
- `Project::rebuild_auto_layers_area(key: LevelKey, source_uid: i64, rect: [i32; 4]) -> Result<()>`, rectangle is `[x, y, width, height]` in source grid cells. Also accepts a tile-killer layer UID. Negative dimensions fail; zero-size edits do nothing. Missing cache triggers a full rebuild.
- `add_auto_rule_group(layer_uid: i64, name: &str) -> Result<i64>`
- `add_auto_rule(layer_uid: i64, group_uid: i64, size: i32) -> Result<i64>`
- `update_auto_rule(layer_uid: i64, group_uid: i64, rule_uid: i64, patch: &Value) -> Result<()>`
- `update_auto_rule_group(layer_uid: i64, group_uid: i64, patch: &Value) -> Result<()>`
- `remove_auto_rule(layer_uid: i64, group_uid: i64, rule_uid: i64) -> Result<()>`
- `remove_auto_rule_group(layer_uid: i64, group_uid: i64) -> Result<()>`
- `reorder_auto_rule(layer_uid: i64, group_uid: i64, rule_uid: i64, index: usize) -> Result<()>`
- `reorder_auto_rule_group(layer_uid: i64, group_uid: i64, index: usize) -> Result<()>`

Rule/group creation uses the common global UID allocator. Rule defaults follow `AutoLayerRuleDef.new`; empty tile rectangles intentionally produce no output until configured. Patches preserve unknown properties and reject UID/child-list replacement. Changing size requires a correspondingly sized pattern in the same patch. Legacy `tileIds` migrate to `tileRectsIds` when edited. Group deletion cleans per-instance optional rule references. Every definition mutation is transactional and regenerates only that definition's layer instances across loaded levels. Reorder indices are zero-based final positions.

## Implemented upstream behavior

- IntGrid and separate AutoLayer sources, instance override tilesets, legacy sparse zero-based IntGrid migration, old tileIds conversion.
- Ordered active rules/groups, reversed painter-order output, ascending coordinate IDs within each rule, retained tile-rectangle order.
- Optional-rule presence behavior, biome OR/AND requirements and absent-field fallback, including the original precedence of biome matching over optional switches.
- Exact positive/negative values, ANYTHING/empty, IntGrid groups, out-of-bounds values, 10-cell relevance buckets.
- X/Y modulos, offsets, checker modes and original checker-axis normalization.
- Flips, symmetry normalization, per-rule flip matching, break-on-match, opaque-tile culling using cached atlas opacity, tile-killer layers.
- Random rectangles, stamp bounds/pivots, tile/layer pivots, signed/random position offsets, atlas padding and spacing.
- LDtk's coordinate RNG with JavaScript floating-point multiplication followed by ToInt32, rather than a wrapping-integer approximation.
- Exact Heaps Perlin gradient table, 50-cell repeat, truncation, scale, octave seeds, normalization, and arithmetic evaluation order. The Heaps MIT notice is embedded with the port.
- Full rebuild computes all outputs before committing; a bad layer cannot leave partially rewritten caches.

## Historical differences: evidence and limits

The 75 historical mismatches are **not all classified as harmless**. Concrete checked cases:

- `tests/bugs/gridVaniaLab.ldtk`: duplicate entries with the same rule/coordinate ID carry incompatible positions after old dimension changes. Example rule 148, cell 32 has both `[0,16]` and `[512,0]`; current width resolves that cell to `[0,16]`. Full regeneration produces the latter single canonical anchor.
- `tests/bugs/rulesBug.ldtk`: saved rule-101 tiles include 36 anchors that no longer match its all-1 3x3 pattern; some saved pixel coordinates exceed the current layer width. Saved caches also violate its current checker distribution.
- `tests/lab2.ldtk`, Level_1: source IntGrid is entirely zero, but cache contains 195 tiles from rules that require positive cells. Rebuild correctly yields no tiles. Level_0 has an old rule-195 stamp at an anchor incompatible with the current pattern/boundary.
- `tests/gridSizeChange.ldtk`, AutoLayer, rule 12/cell 380: old tile 210 versus regenerated 213. Executing installed 1.5.3 `dn_M.randSeedCoords` with the stored seed/coordinate/flip independently gives **213**.
- `tests/ruleRandomOffsets.ldtk`, rule 6/cell 878: old X=72 versus regenerated X=73. Installed 1.5.3 RNG and offset formula independently give **73**.

The last two are retained as explicit historical regression tests. Remaining historical differences require broader original-app migration/rebuild comparison to distinguish historical caches/format changes from any remaining edge cases; they are not silently normalized away. Current official examples have no exceptions.

## Responsiveness

Incremental evaluation borrows the CSV instead of copying it. Only source 10-cell buckets overlapping the changed rule footprint are counted, and only cells inside the changed rectangle expanded by maximum active rule radius are matched. Existing output tiles are indexed in one pass and preserved outside that region; this avoids rescanning every tile once per rule. Returning the authoritative flat JSON array still copies retained tile records, so total update cost includes O(existing output tiles).

Release measurement on `Typical_TopDown_example.ldtk`, first level, 20 iterations (local machine, isolated build of the same evaluator): full rebuild **20.743 ms total / 1.037 ms per update**, one-cell update **5.871 ms total / 0.294 ms per update**. Incremental output was checked against a full rebuild after timing. These are evaluator measurements, not end-to-end editor input/render latency or original-app performance comparisons.


## Rule wizard, cross-group movement and clipboard follow-up

`Project::apply_auto_rule_wizard(layer_uid, group_uid:Option<i64>, name:&str, rules:&[Value])->Result<i64>` replaces/creates one group atomically, marks `usesWizard`, inserts new groups first, reserves fresh rule UIDs without scanning the project per fragment, and compiles affected layer instances once. It ports source trimming of zero borders, redundant symmetric-flip removal, checker-axis normalization and removal of invalid out-of-bounds source values. Empty/invalid names, odd-size violations, invalid patterns/tiles and protected UIDs fail atomically.

`Project::move_auto_rule_to_group(layer_uid,from_group,to_group,rule_uid,index)` moves the actual rule Value and preserves its UID and unknown properties. Index is an insertion index after removal. It recompiles once and rolls back an invalid destination.

The crate-private `autotile::clipboard_rule(uid,changes)` supplies default fields and validates an already UID-stripped modern rule patch for the clipboard worker's batched installation. It preserves extension fields and rejects protected UID/legacy tileIds changes.

Regression evidence: wizard test replaces existing output, verifies fresh IDs, 3×3-to1×1 trimming, symmetric flip cleanup, valid/invalid OOB handling, and full rollback; group-move test verifies identity/extensions/render output and invalid destination rollback. `scripts/cargo test --offline -p ldtk-core --test autotile`: 19 passed, 4 explicitly ignored.
