## Source checks and corrections after the baseline

The original screenshot has an embedded ICC profile; native PNG has no ICC profile. Direct raw-RGB comparisons are invalid. Converting the original through macOS ColorSync to sRGB produces the same far-canvas color as native, **[121,121,154]**. Geometric comparisons do not require conversion.

The original Chest value is **not invalid**: direct CDP reads showed internal wrappers `[Sword, Heavy sword, Bow]`, null default, and `EnumDef.getValue("Heavy sword")` returned `Heavy_sword` with tile rectangle x80/y432. `EnumDef.hx:112` normalizes local enum lookup through `Project.cleanupIdentifier`; external enums use literal identifiers. The initial hypothesis of invalid-value tidying/default fallback was wrong and was rejected before renderer implementation. Native now reuses core `Project::enum_value`, preserving the serialized legacy value.

Fixed and regression-tested: entity field max width 250 and level field max width 800 are raw bitmap pixels, converted by DPR; ruler glyph scale follows the level root (not the screen-scaled field root), labels use project background whitened by .5, handles default to .3 alpha; original .7 white level boundary and outer Gaussian knockout shadow. `shadow-oracle.cjs` executes the installed original Heaps `Blur.calcValues` and records all 18 radius-128 taps in `shadow-oracle.json`. Native uses that same tested kernel in a bounded 161×161 maximum nine-slice texture, with .9 alpha in each separable pass and transparent interior. This avoids a full-level offscreen texture.

All four new source regressions were observed failing before their fixes. The `source_` targeted run passed 17 tests. Full renderer-only verification and corrected real captures are recorded next.

`acceptance-native-entities-corrected.png` was deliberately rejected as acceptance evidence: root's new focus behavior left `capture_state.clicktrap=true`. Harness now sends a real `WindowFocused(true)` event, waits for the source two-frame mask dismissal, then sends input. Captures additionally reject a remaining focus mask. This file must not be used to judge renderer color or performance.

A further direct runtime layout read resolved the remaining text offset: original font `lineHeight=26`, `baseLine=21`; original `10 HP` flow bounds are 47×21 even though `Text.textHeight=26`. At scale 1.5 the parent rounds that row to 71×32 pixels. Native now distinguishes `measure_flow` (baseline on final line) from ordinary text/identifier measurements, converts physical flow margins/spacing by DPR, and rounds scaled parent extents. That regression failed at 23.5×13 logical points before the fix and passed at 23.5×10.5 afterwards. Renderer-only tests now **35 passed, 4 resource-dependent tests ignored**.

The initial border sample difference was draw order: original adds `boundsGlow` after the white bounds in DP_UI, so its knockout shadow also darkens the outer half of the border. Native now follows that order. No compensating opacity guess was used.

The native example runs an explicit foreground-input scenario: it keeps `RawInput.focused=true` and filters OS loss-of-focus events, then routes all synthetic events through the actual `EditorApp::raw_input_hook`. This does not claim the unbundled executable acquired OS foreground ownership. It permits deterministic real GPU captures and input timing while retaining the application's normal focus-mask logic.

The first release recheck exposed another acceptance-harness problem: this simulated-focus process sometimes runs without presentation throttling. The screenshot also requires the configured minimum ready-frame count. Frame-start intervals from this simulated-focus process remain scheduling observations, including possible unthrottled looping, and must not be described as presented FPS or ordinary foreground frame pacing.
